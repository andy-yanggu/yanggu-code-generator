
# 统一字段声明改造方案

## 一、新增 CrudField 类型

在 `src/types/schema/index.ts` 中新增统一字段类型：

```ts
interface CrudField {
  // ====== 共有（三者通用） ======
  key: string
  prop?: string              // 未填时取 key
  label: string              // 必填

  // ====== 视图角色标记 ======
  inForm?: boolean           // 是否出现在表单，默认 false
  inSearch?: boolean         // 是否出现在查询表单，默认 false
  inTable?: boolean          // 是否出现在表格列，默认 false

  // ====== 视图专属子对象（各视图独立声明，不共享） ======
  form?: Partial<FormFieldSchema>
  search?: Partial<SearchFieldSchema>
  table?: Partial<TableColumnSchema>
}
```

**设计要点**：
- 顶层只有 `key` / `prop` / `label` + 视图角色标记，**不做任何属性共享**
- 每个视图的专属属性完全放在 `form: {}` / `search: {}` / `table: {}` 子对象中，互不干扰
- 子对象类型直接复用现有的 `FormFieldSchema` / `SearchFieldSchema` / `TableColumnSchema`（Partial），字段名和含义完全一致
- 即使表单和查询的 `component` / `options` 相同，也需要各自在 `form` 和 `search` 中分别声明——**显式优于隐式**
- 子对象命名为 `form` / `search` / `table`（而非 `formSchema` / `searchSchema` / `tableColumns`），避免与现有 schema 数组的命名产生语义冲突（`formSchema` 是"全部字段的列表"，`form` 是"单个字段在表单中的配置"）
- 子对象可省略：当某个视图不需要额外配置时（如查询字段只需默认 input），不写对应子对象即可，派生时 `...undefined` 安全展开

## 二、派生逻辑（hook 内部）

### 2.1 派生 formSchema

```ts
function buildFormSchema(fields: CrudField[]): FormFieldSchema[] {
  return fields
    .filter(f => f.inForm)
    .map(f => ({
      key: f.key,
      prop: f.prop ?? f.key,
      label: f.label,
      ...f.form   // component / options / ruleList / tooltip 等全部来自子对象
    }))
}
```

### 2.2 派生 searchSchema

```ts
function buildSearchSchema(fields: CrudField[]): SearchFieldSchema[] {
  return fields
    .filter(f => f.inSearch)
    .map(f => ({
      key: f.key,
      prop: f.prop ?? f.key,
      label: f.label,
      ...f.search   // component / options / width 等全部来自子对象
    }))
}
```

### 2.3 派生 tableColumns

```ts
// 内置固定列
const BUILTIN_SELECTION = { key: 'selection', type: 'selection' as const, label: '', width: 50, align: 'center' as const, fixed: 'left' as const, disabled: true }
const BUILTIN_INDEX = { key: 'index', type: 'index' as const, label: '序号', width: 60, align: 'center' as const, disabled: true }
const BUILTIN_OPERATION = { key: 'operation', label: '操作', fixed: 'right' as const, width: 150, align: 'center' as const, disabled: true }
const BUILTIN_CREATE_TIME = { key: 'createTime', label: '创建时间', minWidth: 120, sortable: 'custom' as const, align: 'center' as const }
const BUILTIN_UPDATE_TIME = { key: 'updateTime', label: '修改时间', minWidth: 120, sortable: 'custom' as const, align: 'center' as const }

// 内置列开关（全部默认 true）
interface BuiltinColumnOptions {
  showSelection?: boolean    // 多选列，默认 true
  showIndex?: boolean        // 序号列，默认 true
  showOperation?: boolean    // 操作列，默认 true
  showCreateTime?: boolean   // 创建时间列，默认 true
  showUpdateTime?: boolean   // 修改时间列，默认 true
}

function buildTableColumns(fields: CrudField[], options?: BuiltinColumnOptions): TableColumnSchema[] {
  const cols: TableColumnSchema[] = []

  if (options?.showSelection !== false) cols.push(BUILTIN_SELECTION)
  if (options?.showIndex !== false) cols.push(BUILTIN_INDEX)

  cols.push(...fields.filter(f => f.inTable).map(f => ({
    key: f.key,
    prop: f.prop ?? f.key,
    label: f.label,
    ...f.table   // align / sortable / formatter / width 等
  })))

  if (options?.showCreateTime !== false) cols.push(BUILTIN_CREATE_TIME)
  if (options?.showUpdateTime !== false) cols.push(BUILTIN_UPDATE_TIME)

  if (options?.showOperation !== false) cols.push(BUILTIN_OPERATION)

  return cols
}
```

**内置列开关用法**：
- 默认全部开启，与当前所有页面的行为一致
- 不需要某个内置列时，传 `false` 即可关闭
- 典型场景：纯展示表格 `showSelection: false, showOperation: false`；无批量操作 `showSelection: false`

## 三、useCrud 入参改造

### 3.1 新增 UseCrudOptions 的 fields 模式

```ts
interface UseCrudOptions<VO, Query, DTO> {
  primaryKey?: string
  subject?: string

  // 新模式：统一字段声明
  fields?: CrudField[]

  // 接口（保持不变）
  tableConfig: UseCrudTableOptions<VO, Query>
  formConfig: UseCrudFormOptions<DTO, VO>
}
```

### 3.2 useCrud 内部逻辑

```ts
export const useCrud = (opts: UseCrudOptions) => {
  // 如果提供了 fields，自动派生并注入
  if (opts.fields) {
    const formSchema = buildFormSchema(opts.fields)
    const searchSchema = buildSearchSchema(opts.fields)
    // 内置列开关从 tableConfig 中透传
    const builtinOptions: BuiltinColumnOptions = {
      showSelection: opts.tableConfig.showSelection,
      showIndex: opts.tableConfig.showIndex,
      showOperation: opts.tableConfig.showOperation,
      showCreateTime: opts.tableConfig.showCreateTime,
      showUpdateTime: opts.tableConfig.showUpdateTime
    }
    const tableColumns = buildTableColumns(opts.fields, builtinOptions)

    // 注入到子配置（仅在子配置未显式提供时）
    ;(opts.formConfig as any).formSchema ??= formSchema
    ;(opts.tableConfig as any).searchSchema ??= searchSchema
    ;(opts.tableConfig as any).tableColumns ??= tableColumns
  }

  // 后续逻辑不变...
}
```

**兼容性**：
- `fields` 是可选的。不传 `fields` 时，仍可手动传 `formSchema` / `searchSchema` / `tableColumns`，完全向后兼容
- `initQueryForm` 不参与自动推导——因为 `queryContext` 等场景下自动推导的初始值可能与固定查询上下文冲突，仍由页面自行声明
- 内置列开关通过 `tableConfig` 透传，页面在 `tableConfig` 中设置 `showXxx: false` 即可关闭对应内置列

## 六、注意事项

1. **响应性**：`fields` 是普通数组（不响应），派生结果在 `useCrud` 入口一次性计算即可（与当前 schema 数组的使用方式一致）
2. **ruleList 的归属**：表单的 `ruleList` 放在 `form: {}` 子对象中；查询表单同样支持字段级校验，`ruleList` 放在 `search: {}` 子对象中（`SearchForm.vue` 会消费 `field.ruleList` 构建查询表单的校验规则）
3. **内置列的开关**：5 个内置列（selection / index / operation / createTime / updateTime）全部默认开启，通过 `BuiltinColumnOptions` 的 `showXxx: false` 按需关闭
4. **插槽命名不受影响**：`key` 不变，插槽命名机制与当前完全一致
5. **渐进迁移**：旧写法（直接传 formSchema / searchSchema / tableColumns）完全兼容，新写法（传 fields）是可选的增强
